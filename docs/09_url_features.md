# Задание 9. Модуль анализа URL

**Автор:** Омаров Марлен Еркешович, SIS-2304

Код: `ml/url_features.py`. Тесты: `tests/test_url_features.py` (31 тест, только зарезервированные домены
`example.com`, `example.org`, `.test`, `.example` и адреса из диапазона документации `192.0.2.0/24`).

## 1. Принцип

URL анализируется **только как строка**. Модуль не делает HTTP-запросов, не разрешает DNS и не открывает сокеты.
Библиотека `tldextract` создаётся с параметром `suffix_list_urls=()`, то есть использует встроенный в пакет снимок
Public Suffix List и не скачивает его. Отсутствие сетевых вызовов проверяет тест `test_no_network_access`:
он подменяет функции сокетов на исключение и вызывает извлечение признаков.

## 2. Функции

| Функция | Назначение |
| :--- | :--- |
| `validate_url(url) -> ValidationResult` | Проверка формата: строка, не пустая, до 2048 символов, без пробелов и управляющих символов, схема только `http`/`https`, корректный порт, домен с точкой или IP-адрес. URL без схемы дополняется `http://` **только для разбора**. Возвращает `ok`, нормализованный URL, домен и сообщение об ошибке на русском |
| `extract_url_features(url) -> dict` | 24 признака в фиксированном порядке `FEATURE_NAMES`; для некорректного URL — `InvalidURLError` (подкласс `ValueError`) с понятным сообщением |
| `explain_url(features, url) -> list[str]` | До 6 причин на русском языке, отсортированных по важности |
| `registered_domain(url)` | Регистрируемый домен (`login.secure.example.co.uk` → `example.co.uk`) — для разбиения набора по группам в задании 10 |

Признаки 23–24 добавлены сверх перечня ТЗ.

**Особые случаи:**
* Зоны вне Public Suffix List (`.test`, `.example`, `.local`): последняя метка считается зоной, предпоследняя — доменом.
* Название бренда на его официальном домене не считается подозрительным словом: `kaspi` на `kaspi.kz` — норма,
  на `kaspi-secure-login.example` — признак подделки.
* Слова `mail`, `outlook`, `forte` исключены из поиска брендов в адресе: иначе `mail.google.com` считался бы подделкой mail.ru.
* Смешение алфавитов проверяется внутри одной метки домена (`pаypal` с кириллической «а»), а не по всему адресу:
  кириллический домен в латинской зоне (`каспи.test`) нормален.

**Источник списка подозрительных зон.** Зоны из публикаций Spamhaus «The World's Most Abused TLDs» 2016–2020
(.top, .click, .work, .download, .review, .loan, .men, .pw, .gq, .cf, .ga, .tk, .ml, .stream, .gdn и др.), зоны,
часто встречающиеся в отчётах о злоупотреблениях доменами (.xyz, .live, .monster, .cfd, .buzz, .icu), а также
.zip и .mov, которые легко спутать с именами файлов. Список — эвристика: в этих зонах есть и честные сайты, поэтому
признак учитывается моделью вместе с остальными, а не как самостоятельное правило.

## 4. Пример

```text
http://kaspi-secure-login.example/verify
  n_hyphens_host = 2, n_suspicious_words = 4, brand_in_url = 1, is_https = 0
  Причины:
  • Название бренда стоит в поддомене или пути чужого домена
  • Подозрительные слова в адресе: kaspi, login, secure, verify
  • Много дефисов в домене
  • Соединение без шифрования (HTTP, а не HTTPS)
```
