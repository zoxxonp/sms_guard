## 2. Алгоритм `analyze_sms(text)`

1. Очистка: удаление управляющих символов, обрезка пробелов; пустой текст или > 1000 символов → `AnalysisInputError`.
2. Язык (`detect_language`) и предупреждение о надёжности: для `other` — «язык не представлен в обучающих данных»;
   для `ru`/`kk` — «оценка проверена на искусственных сообщениях».
3. Извлечение URL регулярным выражением: `http://`, `https://`, `www.`, адреса без схемы с известной доменной зоной
   (`bit.ly/...`, `site.kz`), кириллические домены (`.рф`, `.қаз`); завершающая пунктуация отбрасывается, дубликаты
   удаляются, **не более 3 URL**.
4. `P_sms` — SMS-модель (`sms_model.joblib`).
5. Каждая ссылка отдельно: `P_url` — URL-модель, категория `SAFE` / `SUSPICIOUS` / `DANGEROUS` по порогам t1/t2,
   объяснение по признакам (задание 9). `P_url,max` — максимум по ссылкам; если ссылок нет — `null`.
6. Группы социальной инженерии (`ml/rules.py`) + `LINK_REQUEST` (просьба перейти по ссылке при наличии URL).
7. `compute_risk(...)` → Risk Score, уровень, категория, причины, рекомендация.

`analyze_url(url)` — то же для одной ссылки без текста: проверка формата (ФТ-3.1), `P_url`, признаки,
Risk Score по шкале t1 → 35, t2 → 70.

**Ни одна ссылка не открывается**: модули не импортируют сетевые библиотеки, признаки считаются по строке;
`tldextract` работает с встроенным списком доменных зон без загрузки. Тест `test_no_url_is_opened` подменяет
`socket` (connect, getaddrinfo) и проверяет, что анализ проходит без сетевых вызовов.

## 3. Структура результата

`AnalysisResult` (dataclass) содержит все поля примера ответа API (раздел 4.4): `type`, `language`, `category`,
`risk_level`, `risk_score`, `p_sms`, `urls[]` (`url`, `domain`, `p_url`, `category`, причины, признаки), `features`,
`explanation`, `recommendation`, `disclaimer`, `model_versions`, `created_at`; дополнительно — `p_url_max`,
`language_note`, `features_detail`, `applied_overrides`, `processing_ms`. Метод `to_dict()` даёт JSON для API.

## 5. Тесты

`tests/test_services.py` (21 тест) использует маленькие обучаемые на лету модели (`tests/conftest.py`), поэтому
не зависит от больших артефактов: SMS без URL (`p_url_max is None`, `urls == []`), с одним URL, с тремя и с
четырьмя URL (берутся первые три), только URL, официальный домен, `CODE_REQUEST`, пустой/длинный ввод,
управляющие символы, предупреждение о языке, отсутствие сети, однократная загрузка моделей (проверка по логу),
отсутствие файла модели. Эндпоинт `/api/v1/health/` возвращает статус обеих моделей и их версии.
